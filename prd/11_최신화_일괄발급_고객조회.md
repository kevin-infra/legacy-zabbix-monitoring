# 11. 최신화 — 일괄 발급(증정) 처리 + 고객 조회 CRUD

> 공통 컨텍스트는 `00_마스터_PRD.md` 참조.

## 1. 목표
PRD 10에서 선정한 대상 고객에게 기프티콘을 일괄 발급(증정)하는 로직과, 고객이 **본인에게 증정된 기프티콘만** 조회할 수 있는 화면/API를 구현한다. (이 단계에서는 아직 트랜잭션 미적용 — 정합성 보장은 PRD 13에서)

## 2. 배경/컨텍스트
착수보고서 일정상 10/15 작업. "고객: 본인에게 증정된 기프티콘만 조회(필터링)" 요구사항이 핵심.

## 3. 범위
- In-Scope: 일괄 발급 API(1차 버전), 고객별 필터링 조회 API+화면
- Out-of-Scope: 트랜잭션 묶음 처리(PRD 13), 바코드 사용 처리(PRD 12)

## 4. 요구사항
1. `POST /admin/issue` : PRD 10에서 선정된 고객 ID 목록 + 쿠폰 ID를 받아, 각 고객에 대해 `gifticon_transactions`에 발급 이력 insert (1차 버전은 for문 순차 처리 — PRD 13에서 트랜잭션으로 보완)
2. 고객 식별 방식 결정 (로그인 없이 URL 파라미터로 user_id 받을지, 간단 로그인 적용할지 — Kevin과 범위 확정 필요, PRD 10의 관리자 인증 방식과 일관되게)
3. `GET /users/{user_id}/coupons` : 해당 user_id로 발급된 기프티콘만 조회 (`gifticon_transactions` JOIN `gifticon_coupons` WHERE user_id = ...)
4. 고객용 화면: 본인 기프티콘 목록을 카드/리스트 형태로 노출 (상태값 `사용전/사용완료/만료` 표시)
5. 타인의 기프티콘이 노출되지 않는지 반드시 테스트 (다른 user_id로 접근 시 차단되는지 확인)

## 5. 완료 조건 (DoD)
- [ ] 일괄 발급 API로 다수 고객에게 정상 발급 확인
- [ ] 고객별 필터링 조회 정상 동작 (본인 것만 노출)
- [ ] 타인 데이터 접근 차단 테스트 통과
- [ ] `작업명령어_로그.md`에 구현 과정 기록

## 6. 의존 관계
