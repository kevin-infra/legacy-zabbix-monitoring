# 12. 최신화 — 바코드 사용 처리 + 쿠폰 상태 전환

> 공통 컨텍스트는 `00_마스터_PRD.md` 참조.

## 1. 목표
매장에서 바코드를 스캔(또는 입력)해 기프티콘을 사용 처리하는 기능과, 쿠폰 상태(`사용전 → 사용완료 / 만료`)를 전환하는 로직을 구현한다. 이 작업이 끝나면 **CRUD 전체 기능이 완성**된다.

## 2. 배경/컨텍스트
착수보고서 일정상 10/16 작업. "매장에서 바코드 사용 처리", "쿠폰 상태 관리: 사용전 → 사용완료 / 만료 실시간 전환" 요구사항.

## 3. 범위
- In-Scope: 바코드 조회/사용 처리 API, 상태 전환 로직(사용완료/만료), 만료 자동 처리(스케줄러 또는 조회 시점 체크) 방식 결정
- Out-of-Scope: 트랜잭션 정합성 심화 적용(PRD 13에서 전체 재검토)

## 4. 요구사항
1. `POST /coupons/{barcode}/use` : 바코드로 쿠폰 조회 → 상태가 `사용전`이면 `사용완료`로 변경 + `used_at` 기록
   - 이미 `사용완료`거나 `만료`인 쿠폰을 다시 사용 시도하면 에러 응답 (중복 사용 방지)
2. 만료 처리 방식 결정 (택 1 또는 혼합)
   - (A) 배치/스케줄러로 매일 `expiry_date` 지난 쿠폰을 `만료`로 일괄 업데이트
   - (B) 조회 시점에 `expiry_date`를 확인해 즉시 `만료`로 간주 처리 (실시간성 ↑, 구현 간단)
   - 착수보고서의 "실시간 전환" 표현에 더 부합하는 쪽은 (B)이므로 우선 (B)로 구현하고, 여유 있으면 (A) 배치도 추가
3. 상태 전환 시 `gifticon_transactions.used_at` 갱신
4. 관리자/고객 화면에서 상태값이 바로 반영되는지 확인 (조회 API가 최신 상태를 반환하는지)
5. 중복 사용 시도, 만료된 쿠폰 사용 시도 등 예외 케이스 테스트
