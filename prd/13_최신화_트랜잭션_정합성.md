# 13. 최신화 — 트랜잭션 정합성 구현 (BEGIN/COMMIT/ROLLBACK)

> 공통 컨텍스트는 `00_마스터_PRD.md` 참조. ★ 이 PRD는 Plan Mode로 먼저 설계안을 받고 진행할 것 (CLAUDE.md 6번 규칙 — 되돌리기 번거로운 트랜잭션 로직)

## 1. 목표
PRD 11의 일괄 발급 로직을 **하나의 트랜잭션으로 묶어**, 다수 고객 대상 처리 중 일부가 실패하면 전체를 롤백하도록 구현한다. PRD 04에서 재현한 레거시 문제를 최신화에서 해결했음을 증명하는 핵심 단계.

## 2. 배경/컨텍스트
착수보고서 일정상 10/17 작업. "다수 고객 대상 기프티콘 일괄 발급을 하나의 트랜잭션으로 처리, 실패 시 롤백"이 인프라 목표의 필수 항목.

## 3. 범위
- In-Scope: SQLAlchemy(또는 선택한 커넥터) 트랜잭션 적용, 롤백 테스트, PRD 04와 동일 시나리오로 Before/After 비교
- Out-of-Scope: 커넥션 풀 고갈 등 장애 상황 자체는 PRD 14에서 별도 다룸 (단, 트랜잭션 적용이 전제됨)

## 4. 요구사항
1. SQLAlchemy 세션/트랜잭션 패턴 결정 (예: `with session.begin():` 또는 명시적 `try/except`로 `commit()/rollback()`)
2. PRD 11의 일괄 발급 함수를 수정: 고객 목록 전체를 하나의 트랜잭션 안에서 처리
   ```python
   try:
       for user_id in target_users:
           # insert into gifticon_transactions
           ...
       session.commit()
   except Exception:
       session.rollback()
       raise
   ```
3. PRD 04와 **동일한 실패 시나리오**(예: 5번째 고객에서 의도적 오류)로 재현 테스트
4. 결과 확인: 이번에는 1~4번 고객도 DB에 반영되지 않고 **전체가 롤백**되는지 쿼리로 확인
5. Before(레거시, PRD 04)와 After(최신화, 이 PRD) DB 상태를 나란히 비교하는 캡처 자료 작성 (발표자료용)
6. 격리 수준(Isolation Level) 확인 — MySQL 8.4 기본값(REPEATABLE READ)이 이 시나리오에 적합한지 간단히 언급
