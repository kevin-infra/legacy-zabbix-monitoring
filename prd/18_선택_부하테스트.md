# 18. 최신화 — 부하 테스트 (k6/JMeter) [선택]

> 공통 컨텍스트는 `00_마스터_PRD.md` 참조. 우선순위: 선택 — 일정이 밀리면 가장 먼저 제외 가능한 항목(착수보고서 7번 기준)

## 1. 목표
k6 또는 JMeter로 트래픽 폭주 상황을 시뮬레이션해, PRD 14의 장애 재현을 더 체계적인 수치(RPS, 응답시간, 에러율)로 보강한다.

## 2. 배경/컨텍스트
착수보고서 "인프라 목표" 표에 선택 항목으로 명시. PRD 14를 간단한 스크립트로 먼저 재현했다면, 이 PRD는 그것을 정식 부하테스트 도구로 고도화하는 단계.

## 3. 범위
- In-Scope: 도구 선택(k6 권장 — 스크립트 작성이 간단하고 CLI 기반이라 비전공자도 다루기 쉬움), 시나리오 스크립트 작성, 결과 리포트
- Out-of-Scope: CI/CD 연동(PRD 19에서 선택적으로)

## 4. 요구사항
1. k6 설치 (`dnf install` 또는 바이너리 다운로드 — 네트워크 정책 확인 필요)
2. 테스트 시나리오 작성 (JS 파일): 동시 사용자 수를 점진적으로 늘려가며 일괄 발급 API 호출
3. `k6 run scenario.js` 실행
4. 결과 리포트에서 RPS, 평균/최대 응답시간, 에러율 확인
5. PRD 14의 커넥션 풀 고갈 시점을 수치로 특정 (예: 동시 요청 50건부터 에러율 급증)

## 5. 완료 조건 (DoD)
- [ ] k6(또는 JMeter) 설치 및 시나리오 작성 완료
- [ ] 부하테스트 실행 및 리포트 확보
- [ ] PRD 14 재현 시점을 수치로 보강
- [ ] `작업명령어_로그.md`에 기록
