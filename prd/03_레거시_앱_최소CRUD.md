# 03. 레거시 — 앱 최소 CRUD (트랜잭션 미적용)

> 공통 컨텍스트는 `00_마스터_PRD.md` 참조.

## 1. 목표
Node.js(구버전) 앱서버에 "관리자 기프티콘 등록" + "대상 고객 선정 후 일괄 발급" 최소 기능을 구현한다. **의도적으로 트랜잭션을 적용하지 않은 버전**으로 만든다 (PRD 04의 문제 재현을 위한 전제 조건).

## 2. 배경/컨텍스트
착수보고서 일정상 10/9(한글날) 작업. "레거시는 문제 재현·증빙 목적에 한정해 최소 기능으로만 구성" 원칙에 따라, 화면/UI 완성도보다 **트랜잭션 미보호 상태를 재현할 수 있는 최소한의 동작**에 집중한다.

## 3. 범위
- In-Scope: 기프티콘 등록(1건), 대상 고객 다건 선택 후 일괄 발급 API/스크립트, DB insert 로직 (트랜잭션 없이 1건씩 순차 insert)
- Out-of-Scope: 고객 조회 화면, 바코드 사용 처리, 상태 전환 로직(→ 모두 최신화 쪽 PRD 10~12에서 구현)

## 4. 요구사항
1. Express 등 Node.js 경량 프레임워크로 최소 API 서버 구성 (또는 조장님 가이드에 맞는 방식)
2. `POST /coupons` : 기프티콘 1건 등록 → `gifticon_coupons` insert
3. `POST /issue` : 대상 고객 ID 목록을 받아, 각 고객에게 쿠폰을 1건씩 발급 → `gifticon_transactions`에 for문으로 **한 건씩 순차 insert** (BEGIN/COMMIT 없이)
4. 일괄 발급 중 "일부러 중간에 실패하는 상황"을 만들 수 있도록, 특정 고객 ID(예: 존재하지 않는 user_id)를 섞어서 테스트할 수 있게 설계 — PRD 04에서 이 중간 실패를 실제로 재현함
5. 간단한 로그 출력(console.log)으로 몇 번째 고객까지 처리됐는지 확인 가능하게 함

## 5. 완료 조건 (DoD)
- [ ] 기프티콘 등록 API 동작 확인
- [ ] 일괄 발급 API로 정상 케이스(전원 성공) 동작 확인
- [ ] 트랜잭션이 전혀 적용되지 않았음을 코드 상으로 명확히 확인 (BEGIN/COMMIT/ROLLBACK 없음)
- [ ] 모든 명령어/코드 작성 과정이 `작업명령어_로그.md`에 기록됨
