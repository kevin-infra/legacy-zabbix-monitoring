# 14. 최신화 — 장애 시나리오(DB 커넥션 풀 고갈) 재현

> 공통 컨텍스트는 `00_마스터_PRD.md` 참조.

## 1. 목표
명절/연말연시 트래픽 폭주를 가정해, 대량 일괄 발급 요청 시 **DB 커넥션 풀이 고갈되는 장애 상황**을 재현하고, 이를 어떻게 감지·대응할지 확인한다.

## 2. 배경/컨텍스트
착수보고서 일정상 10/18 작업. "명절 트래픽 폭주 가정 → 대량 일괄 발급 시 DB 커넥션 풀 고갈 상황 재현"이 필수 항목. Zabbix(레거시 PRD 05)에서 설계한 임계치 트리거 개념을 최신화 쪽에서도 "재현 및 관찰" 관점으로 연결해볼 수 있음 (단, 최신화 모니터링 자체 구현은 Kevin 범위 아님).

## 3. 범위
- In-Scope: 커넥션 풀 설정값 확인/조정, 대량 동시 요청 생성, 풀 고갈 재현, 에러/대기 상황 캡처
- Out-of-Scope: 최신화용 LGTM 모니터링 구축(정현목님 담당)

## 4. 요구사항
1. SQLAlchemy 커넥션 풀 설정 확인 (`pool_size`, `max_overflow` 등) — 의도적으로 작게 설정 (예: pool_size=5)
2. 대량 동시 요청 생성 방법 결정 (간단한 Python 스크립트로 멀티스레드/비동기 동시 요청, 또는 선택 항목인 k6/JMeter를 앞당겨 사용 — PRD 18 참고)
3. 동시에 pool_size를 초과하는 수의 "일괄 발급" 요청을 날려서 커넥션 풀 고갈 상황 유도
4. 이때 발생하는 에러(타임아웃, `QueuePool limit overflow` 등) 또는 응답 지연을 로그/캡처로 확보
5. 고갈 상황에서 PRD 13의 트랜잭션 정합성이 깨지지 않는지 재확인 (장애 중에도 "부분 반영" 같은 문제가 생기지 않는지)
6. 커넥션 풀 크기를 조정했을 때 증상이 완화되는지 간단 비교 (선택)
