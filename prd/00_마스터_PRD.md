## 1. 프로젝트 개요

- **서비스명**: 기프티콘 증정 서비스 (금융사 가정 시나리오 — 특정 금융사를 벤치마킹하지 않음, 팀 공통 주제: 망분리 금융 환경 Cloud-Native 이관)
- **목적**: 레거시(구버전) 환경에서 발생하는 트랜잭션 미보호 문제를 재현·증빙한 뒤, 최신화(신버전) Cloud-Native 환경으로 이관하면서 트랜잭션 정합성과 장애 모니터링을 갖춘 구조로 재구축
- **담당자 범위 (Kevin)**: 관리자(백오피스) 기프티콘 등록 · 대상 고객 선정 · 일괄 발급(증정) 처리 / 고객 조회(본인 건만 필터링) / 매장 바코드 사용 처리 / 쿠폰 상태 전환(사용전→사용완료/만료)

## 2. 기술 스택 (반드시 준수 — 변경 시 이 문서부터 갱신)

| 구분 | 레거시 | 최신화 |
|---|---|---|
| OS | Rocky Linux 8 | Rocky Linux 10 |
| 웹서버 | Apache | nginx |
| 백엔드 | Node.js (구버전) | FastAPI (Python) |
| DB | MySQL 5.7 | MySQL 8.4 |
| 컨테이너 | — | Docker (추후 K8s Pod) |
| 모니터링 | Zabbix (Agent, 임계치 트리거, 가이드 문서화) | 팀 공통 LGTM 스택 (Kevin 범위 아님) |
| 자동화 | 쉘 스크립트 | Ansible |
| 네트워크 | — | NIC 본딩 필수 / VIP(Keepalived) 선택 |

## 3. DB 테이블 설계 (공통 — 모든 PRD에서 이 스키마 기준으로 작업)

> 접두사 규칙: 모든 테이블명은 `gifticon_` 접두사 필수.

- `gifticon_users` : 고객 정보 (user_id, name, phone, email, created_at 등)
- `gifticon_coupons` : 기프티콘(쿠폰) 마스터 정보 (coupon_id, coupon_name, barcode, expiry_date, status 등 — status는 `사용전/사용완료/만료` 3종)
- `gifticon_transactions` : 발급·사용 이력 (transaction_id, user_id FK, coupon_id FK, issued_at, used_at, status 등)

> 레거시는 위 3개 테이블의 "간단 버전"만 생성하고, 최신화에서 정식 컬럼·제약조건(FK, 인덱스 등)을 설계합니다.

- **DO**: 명령어는 하나씩 풀어서 제시하고, 각 옵션의 의미와 목적까지 설명 (비전공자 학습자 기준)
- **DO**: 모든 작업은 `/home/claude/작업명령어_로그.md`에 "목적 → 명령어 → 옵션 설명 → 결과" 순서로 기록

4. 요구사항 (세부 기능/설정 목록)
5. 완료 조건 (Definition of Done — 체크리스트)

7. 참고 — 기록 규칙 (작업명령어_로그.md에 어떻게 남길지)
