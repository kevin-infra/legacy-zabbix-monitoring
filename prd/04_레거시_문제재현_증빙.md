# 04. 레거시 — 트랜잭션 미보호 문제 재현 및 증빙

> 공통 컨텍스트는 `00_마스터_PRD.md` 참조.

## 1. 목표
PRD 03에서 만든 "트랜잭션 미적용" 일괄 발급 로직을 이용해, 다수 고객 대상 일괄 발급 중 **일부만 처리되고 중단되어 데이터 불일치가 발생하는 상황**을 실제로 재현하고, 스크린샷·영상으로 증빙 자료를 확보한다.

## 2. 배경/컨텍스트
착수보고서 일정상 10/10 작업. 이 증빙 자료는 발표자료(PPT)의 핵심 근거 자료이자, "왜 Cloud-Native 이관이 필요한가"를 실증하는 자료이므로 품질이 중요하다.

## 3. 범위
- In-Scope: 장애 재현 시나리오 설계, 재현 실행, 스크린샷/화면녹화, DB 상태 비교(Before/After), 레거시 서버 정리
- Out-of-Scope: 해결책 구현(트랜잭션 정합성 적용)은 최신화 PRD 13에서

## 4. 요구사항
1. 재현 시나리오 설계: 예) 고객 10명에게 일괄 발급 요청 중, 5번째 고객 데이터에 의도적 오류(존재하지 않는 user_id, DB 제약조건 위반 등)를 섞어 넣기
2. 일괄 발급 API 실행 → 서버 로그에서 몇 번째까지 처리되고 어디서 중단됐는지 확인
3. DB 조회로 "증정 이력(`gifticon_transactions`)에 1~4번 고객만 들어가고 5번 이후는 누락"된 상태를 직접 쿼리로 확인 (`SELECT * FROM gifticon_transactions;`)
4. 이 상태에서 기프티콘 재고(`gifticon_coupons`)와 실제 지급 이력이 서로 맞지 않는 불일치 상태를 캡처
5. 화면 녹화(또는 연속 스크린샷)로 "요청 전송 → 중간 실패 → DB 불일치 확인"까지 전체 흐름을 증빙
6. 증빙 자료 파일명 규칙 정하기 (예: `legacy_tx_fail_01_request.png`, `legacy_tx_fail_02_dbstate.png` ...)
7. 증빙 완료 후 레거시 서버 상태 정리 (운영 유지할지 폐기할지는 선택사항 — 착수보고서 8번 참고)

## 5. 완료 조건 (DoD)
